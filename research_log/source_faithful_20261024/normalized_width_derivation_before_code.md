# Shared normalized-ratio widths before the expanded resource comparison

24 October 2026. New controls only; prior source-reconstruction, compact production files and raw results remain unchanged.

Let S=sumv, taumax=2^tb-1. For each positive item reduce v_i/w_i=a_i/b_i with a_i,b_i positive integers. At a feasible split P<=S and0<=R<=W, so P*b_i+R*a_i<=S*b_i+W*a_i and tau*b_i<=taumax*b_i. Define B=max_i(max(S*b_i+W*a_i,taumax*b_i)); for an empty instance useB=max(S,taumax). Then cb=max(1,bit_length(B)+1) covers every live product and its sum, preserves the same strict comparator, and covers P/tau in the all-fit comparison because b_i>=1. This is a conservative sufficient width, not a tight minimum. It fairly uses the same normalized ratios in both QFT and compact arithmetic. Capacity and integer-value widths remain unchanged; signed-comparison temporary word has cb+1 bits; generic scratch pools take max(wb,vb,cb). Infeasible prefixes remain independently gated, their irrelevant modular arithmetic is uncomputed, and no unsafe bound may affect output.

Compare against a SHARED conservative control cb_old=bit_length(max(S*maxw+W*maxv,taumax*maxw))+1. The normalized bound never exceeds this scalar product bound because a_i<=v_i and b_i<=w_i. It can be much smaller when raw weights/values share large gcds or densities tie. This normalization is an elementary width improvement and is not a new theorem or priority claim. Both arithmetic engines must receive identical cb for a given instance; otherwise a gate/resource ratio could be a width confound.
