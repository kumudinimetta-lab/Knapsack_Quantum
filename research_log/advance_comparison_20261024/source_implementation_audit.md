Date: 24 October 2026, Asia/Calcutta. Bounded read-only audit for the closest-source comparison. ## Conclusion first

The public R1 release contains an executable classical/specialized QTG simulator, classical solvers, a classical QBnB-tree enumeration path and numerical quantum-resource estimators. The audited QBnB path does NOT return or execute a reversible fractional-LP predicate gate netlist. The published supplement already explicitly uses fractional-greedy LP pruning in knapsack QBnB; this broad idea is prior work.

Our explicit clean XOR predicate netlists and scoped basis-state cleanup checks are therefore a concrete implementation-level difference from the inspected R1 QBnB component. They are NOT a demonstrated performance advance over the authors' full QTG search or over all possible implementations of their fractional-greedy model. Our legacy fixed-point wrapper, new exact wrapper/single scan, root-dual banks and compact controls are self-baselines. No numerical cross-source gate/runtime win has been established under a common cost model. Missing upstream gate lists cannot be counted as evidence that ours is faster.

## Released QBnB call path, interface and semantics

1. [`evaluation/04_run_qbnb_benchmark.py`,lines49-62](https://github.com/SoerenWilkening/QTG_0-1Knapsack/blob/R1/evaluation/04_run_qbnb_benchmark.py#L49-L62) selects the Ambainis/Montanaro enumeration mode, calls the C++ binding and logs objective plus an estimated-cycle field. The configured node cap is HARDCODED as10^10 in the released script. SLURM configuration belongs to their experiment environment; it is not a QPU execution path.
2. [`src/bindings/_qtg_bindings.cpp`,lines197-239](https://github.com/SoerenWilkening/QTG_0-1Knapsack/blob/R1/src/bindings/_qtg_bindings.cpp#L197-L239) first obtains the exact optimum via COMBO, copies the input instance into C structs, and calls classical `branch_and_bound` with that optimum as the target. Thus this is an answer-known benchmark condition, not an answer-agnostic online optimization implementation. Its public return struct has an objective and a uint64 estimated-cycle scalar, not circuit/prefix/threshold registers, a recovered quantum witness, gate list or cleanup flag.
3. [`src/simulation/quantum_branch_and_bound.c`,lines3-16](https://github.com/SoerenWilkening/QTG_0-1Knapsack/blob/R1/src/simulation/quantum_branch_and_bound.c#L3-L16) implements the bound in ordinary C arithmetic: accumulate whole-item profits, then form a host `double` profit/weight times residual capacity, floor that term and cast to the integer type. Inputs include a classical residual capacity and first-item index. No quantum state, gate object or fixed-point precision parameter is present.
4. [`src/simulation/quantum_branch_and_bound.c`,lines19-45](https://github.com/SoerenWilkening/QTG_0-1Knapsack/blob/R1/src/simulation/quantum_branch_and_bound.c#L19-L45) recursively explores include/exclude children and increments a classical counter when entering eligible children. It uses native `long` arguments for several quantities and `num_t` elsewhere. The header sets `num_t` to `long long`, ratio type to `double` and resource-count type to uint32. Portability and coefficient-range assumptions need explicit reconciliation before running high-bit stress on Windows.
5. [`src/simulation/qtgcount.c`,lines531-582](https://github.com/SoerenWilkening/QTG_0-1Knapsack/blob/R1/src/simulation/qtgcount.c#L531-L582) computes scalar cycle estimates. The diffusion estimator takes a maximum over assignment depths, assumes parallel evaluation for the two child assignments, and doubles a counter to account for reversal. The fractional-greedy cost helper adds comparison and QFT/subtraction-cycle formulas; it does not emit the fractional-value arithmetic or a threshold-pruning gate sequence.
6. [`src/bindings/_qtg_bindings.cpp`,lines227-237](https://github.com/SoerenWilkening/QTG_0-1Knapsack/blob/R1/src/bindings/_qtg_bindings.cpp#L227-L237) multiplies the estimated diffusion cost by a schedule built from classically enumerated node count and instance size. The source includes dyadic rounding and a prefactor containing0.1, so reproducing it as simply sqrt(T*n) would omit parts of the actual implementation.

Taxonomy: the C recursion is classical MEASURED work if actually run; this audit did not run it. Their cycle estimators are DERIVED scalar models, the chosen phase-estimation-use budget is SCHEDULED, and the resulting product is a DERIVED modeled work quantity. The upstream return name includes `elapsed_cycles_lb`; that name does not make it a measured QPU/CPU duration or a lower-bound theorem certified by this audit.

## Precision, gate model, cleanup and testing

- The host fractional calculation uses floating arithmetic followed by floor. There is no k-bit coherent efficiency-truncation register or declared accuracy parameter in `bnb_greedy`. Host float behavior must not be described as the precision of a synthesized quantum divider. No quantum divider implementation was found in the audited QBnB call path, so claiming our circuit 'eliminates the authors' divider' would be false.
- `cost_reg_size` uses the capacity's bit length; `profit_reg_size` uses a chosen classical profit upper bound. QFT cycle/gate functions return symbolic integer formulas from register size. Their `COPPERSMITH` selector is described by the source as the original QFT without swaps, not evidence that a fully approximated Clifford+T circuit with a shared error budget has been generated.
- The supplementE.3/E.4/E.5 does give QFT arithmetic/comparison constructions and resource assumptions, including known constants and reuse of multi-control ancillas. This is substantial prior implementation analysis. The audit must not reduce it to 'no circuits exist.' The narrower finding is that their published QBnB branch-bound metric is implemented as classical enumeration plus resource counters, not the same clean predicate interface as ours.
- The factor for reversing the bound appears in the resource counter, but no QBnB workspace state is propagated through a gate list to demonstrate reset. Accounting for reversal is different from executing and checking cleanup. This does not prove their proposed reversible construction cannot clean its workspace.
- `tests/test_solvers.py`,lines120-128, tests that returned QBnB objective/cycle scalars are positive. It does not exhaust arbitrary quantum prefix/depth/threshold/target encodings or measure dirty-workspace columns. That is a difference in checked scope, not evidence of a wrong optimizer.
- The separate QTG branch uses a specialized state/probability representation and analytical amplitude-amplification calculations (`src/common/stategen.c`, `src/simulation/simulate.c`, `src/bindings/_qtg_bindings.cpp`). Its README advertises a QTG simulator and classical solvers. It is not a Qiskit-style generic full-gate statevector engine, but it is executable implementation and must be treated as a real competing method.

## Published supplement versus implementation

SupplementF.2 explicitly states the fractional-greedy bound and adopts favorable benchmarking assumptions: known optimum/tree size, perfect subroutine success, dominant backtracking and a beta=1 search scale. The R1 binding indeed uses COMBO ground truth and a classical node count, while its actual schedule includes additional constants/rounding. No new theorem or numbered algorithm appears in F.2; cited general quantum-tree-search theorems are not re-certified here.

Important node-count mismatch for any direct comparison: R1 increments only when entering a child that passes its pre-entry tests and does not separately count the root in that variable. Our `trees.py::enumerate_threshold_tree` explicitly counts its root and all generated children, including rejected capacity/bound leaves. The exclude-side bound and stop-on-first behavior also differ between code paths/modes. Therefore the two raw node counters are not interchangeable, even on identical weights and values. A ratio across them cannot be interpreted as a pruning benefit until a shared vertex definition and branching/threshold policy are implemented and checked.

The audit also notes source details requiring independent semantic review before any definitive released-code rerun: native-long widths depend on platform; the recursion's stopping guard includes a pointer-null comparison and a final control path without an explicit return; density ordering must be verified at the caller/export boundary. These observations are NOT a verdict that the paper's reported outcomes are wrong. This task did not compile, execute or patch the reference release, and no win is attributed to potential defects.

## Concrete feasible next comparison, with barriers explicit

A bounded honest external comparison can start with a frozen subset of small primary-paper instance files, a documented export of our already-registered inputs, and one shared target per condition. Preserve R1 byte hashes and publish any wrapper separately. First establish exact objective/bound agreement and a common tree-vertex convention; separately report the authors' original answer-known schedule and our structural schedule. Do not use optimum-known targets as an online optimizer or ignore capped/failed runs. This measures semantic/structural comparability, not full quantum performance.

For the substantive circuit-level question, the missing like-for-like reference artifact is an upstream R1 function that emits the complete coherent fractional-LP pruning oracle, with its threshold/depth interface, precision convention and clean ancillas. None was found in the audited released call path. The fair options are: (a) obtain an author-provided circuit if one exists outside this archive; or (b) transparently reconstruct the supplement's bound using its published QFT primitives and then check it on the identical tiny input domain before common-basis synthesis. Option(b) is OUR reconstruction of a prior design, not the authors' released implementation. Reconstructing ordinary add/subtract/QFT primitives is feasible, but the omitted fractional-bound/encoding/error details must be resolved rather than guessed. A common error and connectivity model, controlled operations and workspace allocation are necessary before comparing resources.

Building the released package requires C/C++, CMake, GMP, GSL, pybind11, a Conan/scikit-build path and platform assumptions. This audit deliberately did not install/build those dependencies. Thus an end-to-end reference rerun has not been established as immediately runnable on this Windows workspace; that is a remaining reproducibility task, not a discovered performance disadvantage.

A substantial advance over prior quantum algorithms remains UNRESOLVED. The verified result is narrower: explicit clean gate-list predicates and a matched internal pruning/resource study extend the implementation detail of the inspected R1 QBnB estimator. Whether that constitutes a sufficiently significant research contribution requires the common-model comparison and wider priority review; absence of a released netlist and favorable self-baseline numbers do not settle it.
